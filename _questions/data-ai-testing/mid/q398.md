## The Intent
The interviewer is checking whether you can operationalise drift detection as a concrete monitoring practice, not just define what drift is. At mid level, they want to see tool choice, threshold setting, and alert design — the implementation decisions that turn the concept into a working monitor.

## The STAR Script
**Situation:** Our product used an ML model to predict which users were likely to upgrade to a paid subscription. The model had been trained on data from 18 months ago. The growth team had noticed that the model's upgrade predictions had become less accurate — users predicted as high upgrade likelihood were converting at a lower rate than expected — but no monitoring was in place to explain why or when the degradation had started.

**Task:** I was asked to implement drift detection that would have caught the degradation earlier and would alert on future drift before it affected business metrics.

**Action:** I implemented drift detection across three categories of model input features. Numerical features: for continuous features (session duration, pages viewed, days since signup), I used PSI (Population Stability Index) computed weekly — comparing the distribution of each feature in the past 7 days of production traffic against the training dataset distribution. PSI between 0.1 and 0.2 triggered a warning; above 0.2 triggered an alert. I used Evidently AI to generate the PSI reports automatically. Categorical features: for categorical features (user plan type, acquisition channel), I used chi-square tests comparing the frequency distribution of each category value in production against training. A p-value below 0.05 (after Bonferroni correction for multiple comparisons) triggered an alert. Missing value rate: I tracked the proportion of null values in each feature weekly and alerted if any feature's null rate increased by more than 5 percentage points relative to the training baseline — a common signal that an upstream data source had changed. I also set up a retrospective analysis of the existing logs: applying the drift monitors to 18 months of historical production data showed that significant drift in `days_since_signup` had begun approximately 5 months ago — the product had acquired a large cohort of new users whose behaviour was structurally different from the cohort the model had been trained on.

**Result:** The retrospective confirmed drift was the root cause of the accuracy degradation and pinpointed when it started. The model was retrained on recent data, restoring accuracy. The drift monitors were deployed and fired their first alert six weeks later — catching a distribution shift in `acquisition_channel` caused by the launch of a new paid marketing channel. The data science team was able to investigate and decide whether to retrain before any business impact was observed.

## Key Terms

| Term | Definition |
|------|------------|
| **PSI (Population Stability Index)** | A metric measuring the shift in a feature's distribution between two periods — values below 0.1 indicate no significant change, 0.1–0.2 indicate moderate shift, above 0.2 indicate significant drift |
| **Kullback-Leibler (KL) divergence** | An information-theoretic measure of how one probability distribution differs from another — used as an alternative drift metric to PSI |
| **Chi-square test** | A statistical test assessing whether the frequency distribution of a categorical variable has changed significantly between two samples |
| **Bonferroni correction** | A statistical adjustment that reduces the significance threshold when multiple tests are performed simultaneously — preventing false positive alerts from multiple feature comparisons |
| **Null rate drift** | An increase in the proportion of missing values for a feature — often indicating a change in an upstream data source rather than a genuine distribution shift |
| **Evidently AI** | An open-source ML monitoring library that generates data drift and model quality reports, supporting PSI, statistical tests, and distribution visualisations |
| **Retraining trigger** | A defined condition — such as a PSI threshold breach or accuracy audit failure — that initiates a model retraining cycle |
