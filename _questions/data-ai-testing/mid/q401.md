## The Intent
The interviewer is checking whether you treat lineage as a testable property, not just a documentation artefact. Inaccurate lineage — where the documented relationships between data assets do not match the actual data flow — makes impact analysis unreliable and incident diagnosis slower. At mid level, they want to see that you have verified lineage correctness in practice.

## The STAR Script
**Situation:** Our data platform used dbt to document lineage between models, and we had integrated OpenLineage to capture runtime lineage from our pipeline executions. A data engineer had manually updated a dbt model to read from a new source table without updating the lineage documentation — when a downstream dashboard broke after the source table was deprecated, the lineage graph showed no connection between the dashboard and the deprecated table, so the impact was not predicted.

**Task:** I was asked to implement tests that would catch lineage documentation gaps — where the actual data flow differed from the documented lineage.

**Action:** I designed three lineage tests. Test 1 — documented vs runtime lineage comparison: I wrote a script that compared the lineage captured by OpenLineage during pipeline execution (the actual tables read and written) against the lineage defined in dbt's manifest.json (the documented lineage). Any table that appeared in the runtime lineage but not in the dbt documentation triggered a lineage gap alert. This caught the undocumented source table change immediately when I ran it retrospectively. Test 2 — orphan detection: I queried the lineage graph to identify tables that had no documented upstream source (potential undocumented external dependencies) and tables that had no documented downstream consumers (potentially deprecated tables still being maintained). I found 4 tables with no consumers that were still being computed and loaded on every pipeline run — unnecessary compute cost. Test 3 — column-level lineage validation: For the five highest-priority models (feeding executive dashboards and ML features), I verified column-level lineage by tracing each output column back to its source column through every transformation. I confirmed that the documented transformation matched the actual SQL logic by comparing the lineage metadata against the dbt model SQL. I found one case where a column in the lineage was documented as coming from `orders.total_amount` but the actual SQL was reading from `orders.net_amount` — a semantic error that had been silently present for months.

**Result:** The lineage gap test was added to the CI pipeline — any dbt model change that altered the actual data sources without updating the lineage documentation would fail the check. The orphan table cleanup saved an estimated 15 minutes of compute per daily run. The column-level lineage error was traced to an incorrect dashboard metric that had been reported to the finance team for three months — the metric was corrected.

## Key Terms

| Term | Definition |
|------|------------|
| **Data lineage** | A map of how data flows from source systems through transformations to destinations — used for impact analysis, incident diagnosis, and compliance |
| **Runtime lineage** | Lineage captured automatically during pipeline execution, recording the actual tables and columns read and written — as opposed to statically documented lineage |
| **OpenLineage** | An open standard and ecosystem for capturing and sharing data lineage metadata from pipeline executions across different tools and platforms |
| **Lineage gap** | A discrepancy between documented and actual data flow — indicating that lineage metadata is incomplete or outdated |
| **Orphan table** | A table in the data platform with no documented downstream consumers — a candidate for deprecation or a signal of missing lineage documentation |
| **Column-level lineage** | Lineage tracking at the granularity of individual columns rather than tables — enabling precise impact analysis and semantic correctness verification |
| **dbt manifest** | A JSON artefact generated by dbt containing the full metadata for all models, including their documented lineage — used programmatically for lineage analysis and testing |
