## The Intent
The interviewer is checking whether you understand database transactional guarantees as testable properties, not just theoretical concepts. Applications that read and write databases in production are constantly exercising ACID guarantees — and a QA engineer who can test them finds defects that functional testing alone misses.

## The STAR Script
**Situation:** My team was building a financial ledger system where a payment transaction required two database operations to complete atomically: debit the sender's account and credit the recipient's account. If either operation failed, both had to roll back. A bug report from QA in a previous sprint had noted that if the credit operation failed after the debit succeeded, the debit was not being rolled back — money was leaving the sender's account but not arriving in the recipient's.

**Task:** I was asked to design tests for all four ACID properties of the payment ledger to prevent this class of defect and ensure the system's transactional guarantees held under concurrent load.

**Action:** I tested each property separately. Atomicity: I wrote a test that forced the credit operation to fail (by temporarily making the recipient account ID invalid) after the debit had succeeded, and asserted that the sender's balance was unchanged after the rollback — confirming the partial transaction was fully reversed. I also tested the reverse: forcing the debit to fail and confirming neither account changed. Consistency: I tested that the database's constraints were never violated — specifically, that account balances could not go below zero (a CHECK constraint), and that a transfer to a non-existent account number returned a constraint violation rather than creating an orphan transaction record. Isolation: I wrote a concurrent test using Python's `threading` module — two threads simultaneously attempted to transfer the full balance of the same account to different recipients. I ran this 100 times and asserted that in every case, only one transfer succeeded and the account balance was never negative, confirming serialisable isolation was in effect. Durability: I wrote a test that committed a transaction and then simulated a database restart (using Docker to stop and restart the database container), then verified the committed transaction was present after the restart.

**Result:** The atomicity test confirmed the existing bug — the partial rollback was not working. Investigation revealed the application was using two separate database connections for the debit and credit operations rather than a single transaction, so the rollback only applied to the second connection. The fix wrapped both operations in a single database transaction. The isolation test found that under high concurrency, accounts occasionally went negative — the isolation level was set to READ COMMITTED rather than SERIALIZABLE. The isolation level was corrected for financial operations.

## Key Terms

| Term | Definition |
|------|------------|
| **Atomicity** | The ACID property guaranteeing that a transaction either completes fully or has no effect — partial completion is not permitted |
| **Consistency** | The ACID property guaranteeing that a transaction brings the database from one valid state to another, never violating defined constraints |
| **Isolation** | The ACID property guaranteeing that concurrent transactions do not interfere with each other — as if they had run sequentially |
| **Durability** | The ACID property guaranteeing that committed transactions survive system failures and restarts |
| **Isolation level** | A configuration setting controlling how much concurrent transactions can see each other's uncommitted changes — options include READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, and SERIALIZABLE |
| **Rollback** | The reversal of all changes made by a transaction when it fails or is explicitly aborted — the mechanism that enforces atomicity |
| **CHECK constraint** | A database rule that verifies a column value satisfies a defined condition before the row is accepted — for example, `balance >= 0` |
