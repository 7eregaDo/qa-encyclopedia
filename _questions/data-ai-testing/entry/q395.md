## The Intent
The interviewer is checking whether you can apply API testing thinking to ML model endpoints — recognising that a model endpoint is an API with additional quality dimensions specific to ML. This is one of the most accessible entry points into AI testing, because it builds directly on existing API testing skills.

## The STAR Script
**Situation:** My team deployed a machine learning model as a REST API endpoint — `POST /predict` — that took a JSON body with customer features (age, account tenure, product usage score) and returned a churn probability between 0 and 1. I was asked to write tests for the endpoint before it was connected to the production application.

**Task:** I designed tests covering both the input handling and the output behaviour of the model endpoint.

**Action:** I structured the tests in two groups. Input tests — I tested the same categories I would for any API. Valid input: a well-formed request with all required fields returned a 200 with a response body containing a `churn_probability` field. Missing required field: omitting `account_tenure` returned a 422 with an error message naming the missing field. Wrong type: sending `age` as a string ("thirty") returned a 422. Out-of-range value: sending `age` as -5 returned a 422 — negative ages are not valid. Null values: sending `product_usage_score` as null was ambiguous — I checked the documentation, confirmed null was not permitted, and verified the endpoint returned 422. Empty body: returning 400. I also tested a preprocessing consistency check: I sent the same feature values that appeared in the model's training data documentation and verified the endpoint did not apply any transformation that would change the feature values before passing them to the model (some endpoints normalise inputs; I wanted to confirm the normalisation matched what was done at training time). Output tests — I tested the output contract. Schema: the response always contained `churn_probability` as a float between 0 and 1. Boundary outputs: I sent a feature vector designed to represent a very low-risk customer (long tenure, high usage) and verified the probability was below 0.1; a high-risk vector (very short tenure, zero usage) and verified the probability was above 0.7. Consistency: I sent the same input five times and verified the output was identical each run (the model was deterministic, not probabilistic).

**Result:** The out-of-range age test returned a 200 with a prediction rather than a 422 — the endpoint was not validating input ranges before passing them to the model. The model returned a prediction for an impossible input (age -5), which was a silent failure. Input validation was added. The preprocessing test also found that the endpoint was normalising `product_usage_score` using a different scale than the training pipeline — a feature preprocessing mismatch that would have degraded model accuracy in production.

## Key Terms

| Term | Definition |
|------|------------|
| **Model endpoint** | A REST API that exposes a machine learning model for inference — accepting feature inputs and returning predictions |
| **Feature preprocessing** | Transformations applied to raw input values before they are passed to a model — such as normalisation, encoding, or imputation — which must be consistent between training and serving |
| **Training-serving skew** | A class of defect where the preprocessing applied at serving time differs from that applied during training — causing the model to receive inputs in a different format than it was trained on |
| **Prediction range** | The expected bounds of a model's output — for example, a probability must be between 0 and 1, and predictions outside the expected range signal a quality issue |
| **Input validation** | The enforcement of type, range, and presence constraints on model inputs before they are passed to the model — preventing malformed inputs from producing silent errors |
| **Deterministic model** | A model that produces identical outputs for identical inputs on every call — as opposed to a generative model with stochastic output |
| **Feature vector** | A structured set of input values representing one instance, passed to a model to generate a prediction |
