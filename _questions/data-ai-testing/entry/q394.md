## The Intent
The interviewer is checking whether you understand schemas as contracts — and that schema violations are defects, not just formatting issues. Schema conformance testing is one of the most fundamental data quality practices, and a QA engineer who understands it can apply it immediately in any data context.

## The STAR Script
**Situation:** My team received a daily JSON file from a third-party data vendor containing product catalogue updates. The file was loaded directly into our database by an automated process. After three months of operation, a product manager reported that some product prices were displaying as zero on the website — which turned out to be caused by the vendor occasionally sending the `price` field as a string ("12.99") rather than a number (12.99), which our database treated as a failed cast and stored as null, then displayed as zero.

**Task:** I was asked to implement schema validation on the incoming file that would catch type mismatches before they reached the database.

**Action:** I wrote a schema definition for the expected file format using Python's `jsonschema` library. The schema specified: required fields (`product_id`, `name`, `price`, `category`, `in_stock`), data types for each (`product_id`: integer, `price`: number, `in_stock`: boolean), and value constraints (`price` must be greater than or equal to zero, `category` must be one of a defined set of accepted values). I added a validation step at the start of the load process that ran every incoming file against the schema before any records were written to the database. If any record failed validation, the entire file load was rejected and an alert fired to the data team with the specific field, record, and violation type. I also wrote a set of test cases for the validation logic itself — using deliberately malformed JSON files to confirm the validator caught each violation type correctly.

**Result:** The schema validator caught a vendor-side type error in the first week: 14 records had `price` as a string. The load was rejected and the vendor was notified. They corrected the file and resubmitted within two hours. The data team also used the schema definition as the basis for their vendor contract amendment — the schema became the documented expectation the vendor was contractually required to meet.

## Key Terms

| Term | Definition |
|------|------------|
| **Data schema** | A formal specification of a dataset's structure — field names, types, required presence, and value constraints |
| **Schema validation** | The process of verifying that a data record or dataset conforms to its defined schema — detecting type mismatches, missing fields, and invalid values |
| **JSON Schema** | A vocabulary for defining the structure and constraints of JSON data — widely used for validating API payloads and data files |
| **Type mismatch** | A schema violation where a field contains a value of the wrong data type — such as a string where a number is expected |
| **Required field** | A field that must be present and non-null in every record — its absence is a schema violation |
| **Value constraint** | A rule that a field's value must satisfy — such as a minimum value, a maximum length, or membership in an allowed set |
| **Schema contract** | A formal agreement between a data producer and consumer specifying the schema the producer must maintain — analogous to an API contract for data |
